# /screen

## 목적

여러 후보 종목을 **빠르고 저렴하게** 걸러낸다. `/trade-team`(4-agent 병렬)을 아무 종목에나 돌리면 토큰 비용이 크므로, 이 스킬로 먼저 명백히 탈락할 후보를 제거한 뒤에만 `/trade-team`을 실행한다.

**핵심 차이 — `/trade-team`과 비교**: 이 스킬은 서브에이전트를 병렬로 띄우지 않는다. 메인 에이전트 하나가 순차적으로 하드 메트릭을 확인하고 즉시 Pass/Fail을 매긴다. 깊은 해석이나 관점 대립은 다루지 않는다 — 그건 `/trade-team`의 역할이다.

## 입력

```
/screen $ARGUMENTS
```

`$ARGUMENTS`는 공백으로 구분된 티커 목록이다 (예: `/screen AAA BBB CCC`).

## 하드 메트릭 (7개, 전부 Pass/Fail 이진 판정)

절충 없음 — 애매하면 Fail로 처리하고 사유에 "데이터 불충분"이라고 명시한다.

1. **유동성** — 평균 일일 거래대금이 의미 있는 포지션을 무리 없이 체결할 수 있는 수준인가? (예: 최근 20일 평균 거래대금이 계좌 목표 포지션 규모의 최소 수십 배 이상)
2. **변동성 적정 범위** — ATR%(또는 동등 지표)가 너무 낮아(사실상 안 움직임) 무의미하거나, 너무 높아 리스크 관리가 불가능한 범위는 아닌가?
3. **최소 추세 방향성** — 완전한 무추세 노이즈 구간은 아닌가? (깊은 추세 분석은 `/trade-team`의 `agents/trend-analyst.md` 몫 — 여기서는 "방향이 아예 없다"만 거른다)
4. **호가 스프레드** — 매수/매도 스프레드가 과도해서 진입·청산 비용이 기대 수익을 갉아먹을 수준은 아닌가?
5. **임박한 이벤트 리스크** — 실적발표, 정책 발표 등 확인된 고변동성 이벤트가 며칠 내로 임박해 있는가? (임박해 있으면 Fail 또는 Watch로 별도 표시)
6. **손절선 설정 가능 여부** — `tools/trading_rigor.py risk-reward`로 계산했을 때 합리적인 리스크·리워드 비율(예: 1:2 이상)이 나오는 손절/목표 지점을 잡을 수 있는가?
7. **데이터 확보 가능 여부** — 위 6개 항목을 판정할 최소한의 공개 데이터가 확인되는가? (비상장, 신규상장 직후 등으로 확인 불가하면 이 항목부터 Fail)

## 실행 순서

1. 입력된 각 티커에 대해 위 7개 메트릭을 순서대로 확인한다.
2. 계산이 필요한 항목(6번)은 암산하지 않고 `tools/trading_rigor.py risk-reward`를 사용한다.
3. 데이터 출처가 하나뿐이면 신뢰도를 🟡로 표기한다 (이 스킬은 저비용이 목적이므로 `/trade-team`만큼의 교차검증은 요구하지 않되, 표기는 생략하지 않는다).
4. 7개 중 하나라도 Fail이면 해당 티커는 **Fail**로 최종 판정한다.
5. 전부 Pass인데 5번(임박한 이벤트 리스크)만 별도로 걸리면 **Watch**로 표시한다 (이벤트 통과 후 재평가 권장).
6. 전부 Pass면 **Pass** — `/trade-team` 대상 후보로 넘긴다.

## 출력 포맷

```
# /screen 결과 (<기준일>)

| 티커 | 판정 | 탈락/주의 사유 |
|---|---|---|
| AAA | Pass | - |
| BBB | Fail | 유동성 부족 (평균 거래대금 기준 미달) |
| CCC | Watch | 3일 내 실적발표 임박 — 발표 후 재평가 |

## 다음 단계
Pass 판정 종목만 `/trade-team <티커>`로 이어서 심층 분석하세요.
```
