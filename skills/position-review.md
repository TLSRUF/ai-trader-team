# /position-review

## 목적

이미 보유 중인 포지션에 대해, 진입할 때 세운 근거(테제)가 지금도 유효한지 빠르게 재점검한다. `/trade-team`이 "진입할 것인가"를 다룬다면, 이 스킬은 "그 판단이 아직 맞는가"를 다룬다.

**핵심 차이 — `/trade-team`과 비교**: 처음부터 풀 리서치를 다시 하지 않는다. 4개 관점(`agents/*.md`)의 핵심 질문만 현재 시점 기준으로 빠르게 재확인하고, 최초 판단과 대조한다. `/screen`처럼 단일 에이전트로 순차 실행한다 (병렬 서브에이전트 없음).

## 입력

```
/position-review $ARGUMENTS
```

`$ARGUMENTS`는 `<티커> [최초 진입 근거 요약]` 형태다.

최초 진입 근거를 직접 안 주면, 아래 순서로 조회한다:

1. `reports/positions.md`에서 해당 티커 행을 찾는다 — 있으면 "최초 테제" 칸을 우선 사용한다.
2. 없으면 `reports/`에서 해당 티커의 가장 최근 `/trade-team` 리포트를 찾는다 (파일명 규칙: `<날짜>-<티커>-trade-team.md`).
3. 그것도 없으면 사용자에게 최초 진입 근거를 한두 문장으로 요약해달라고 요청하고, 없이는 드리프트 대조를 할 수 없으므로 진행하지 않는다.

## 실행 순서

1. **최초 테제 확보**: 위 조회 순서대로 최초 진입 근거(가능하면 관점별 태그/점수까지)를 확보한다.
2. **현재 상태 재확인**: `agents/trend-analyst.md`, `agents/macro-analyst.md`, `agents/risk-manager.md`, `agents/flow-analyst.md` 각각의 "핵심 질문"만 현재 데이터로 다시 확인한다. 전체 근거를 새로 작성하지 않고, 최초 판단과 달라진 점 위주로 짧게 서술한다.
3. **관점별 드리프트 판정**: 관점마다 최초 태그(Bull/Bear/Neutral)와 현재 태그를 비교해 아래 중 하나로 분류한다.
   - **동일**: 태그 불변
   - **약화**: 태그는 같지만 근거가 약해짐 (예: Bull 유지, 점수 하락)
   - **반전**: 태그 자체가 바뀜 (예: Bull → Bear/Neutral)
4. **종합 드리프트 심각도**:
   - **없음**: 전 관점 동일 또는 강화
   - **경미**: 1개 관점만 약화, 반전 없음
   - **심각**: 반전이 1개 이상 있거나, 리스크 관점이 약화·반전됨 (리스크는 다른 관점보다 가중치를 둔다)
5. **역방향 검증** (심각도가 "없음"/"경미"라 "유지"로 기울 때만 수행): 대응 제안을 확정하기 전에, 반대로 "지금 청산해야 하는 이유"를 관점별 드리프트 표(특히 약화·반전된 항목)를 근거로 먼저 재구성한다. 이 반대논거가 심각도 판정을 뒤집을 만큼 강하면 심각도를 한 단계 올려 재판정한다. 이미 "심각"으로 판정된 경우(청산/축소 검토 방향)에는 절충 없이 그대로 확정하므로 이 단계를 생략한다.
6. **대응 제안**: 위에서 확정한 심각도에 따라 유지 / 축소 검토 / 청산 검토 중 하나를 명확히 제시한다. 애매하게 "지켜보자"로 끝내지 않는다.

## 출력 포맷

```
# /position-review 리포트 — <티커> (<기준일>)

## 최초 테제 요약
<확보한 최초 근거, 출처(리포트 파일 또는 사용자 입력) 명시>

## 관점별 드리프트
| 관점 | 최초 판단 | 현재 판단 | 드리프트 |
|---|---|---|---|
| 추세 | Bull/Bear/Neutral | Bull/Bear/Neutral | 동일/약화/반전 |
| 매크로 | ... | ... | ... |
| 리스크 | ... | ... | ... |
| 수급 | ... | ... | ... |

## 종합 드리프트 심각도
없음 / 경미 / 심각 — <한줄 사유>

## 역방향 검증
<"지금 청산해야 하는 이유" 반대논거 — 심각도가 이미 "심각"이면 "심각 판정 확정 — 역방향 검증 생략"> — 판정: 심각도 유지 / 한 단계 상향

## 대응 제안
유지 / 축소 검토 / 청산 검토
- 근거: ...

## 데이터 신뢰도
🟢/🟡/🔴 <요약>
```

## 리포트 저장

위 출력 포맷으로 작성한 리포트를 채팅 응답으로만 끝내지 않고, `reports/<날짜>-<티커>-position-review.md`에 파일로도 저장한다 (`reports/README.md` 규칙 — 실제 실행 결과는 이 폴더에 남긴다).

- 같은 날 같은 티커로 재실행하면 기존 파일을 덮어쓴다. 다른 날 재실행한 경우는 새 날짜로 별도 파일을 남겨, 드리프트 판정 이력 자체가 사라지지 않게 한다 (`/trade-team`과 동일한 방침).
- 저장 후, 저장한 파일 경로를 사용자에게 알린다.
