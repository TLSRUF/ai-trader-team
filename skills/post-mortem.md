# /post-mortem

## 목적

이미 청산한 포지션을 돌아본다. `/position-review`가 "보유 중인 판단이 아직 유효한가"를 다룬다면, 이 스킬은 "그 판단은 결국 맞았는가, 그리고 다음엔 뭘 다르게 할까"를 다룬다.

**핵심 차이 — `/position-review`와 비교**: `/position-review`는 "청산 전"에 반복적으로 실행하는 드리프트 점검이고, `/post-mortem`은 "청산 후" 한 번 실행하는 회고다. 계산은 암산하지 않고 `tools/trading_rigor.py realized-pnl`로 수행한다.

## 입력

```
/post-mortem $ARGUMENTS
```

`$ARGUMENTS`는 `<티커> [실제 청산가]` 형태다.

1. `reports/positions.md`에서 해당 티커 행을 찾는다. "상태"가 `청산 (YYYY-MM-DD)`가 아니면(아직 보유중이거나 원장에 없으면) 이 스킬은 진행하지 않는다 — 보유 중인 포지션은 `/position-review`를 사용하라고 안내한다.
2. 실제 청산가는 다음 순서로 조회한다: 인자로 받은 값 → 원장의 "청산가" 칸. 둘 다 없으면 사용자에게 요청하고, 답이 없으면 진행하지 않는다.
3. 최초 테제는 원장의 "최초 테제" 칸(또는 그 안에 링크된 `/trade-team` 리포트)에서 확보한다.

## 실행 순서

1. **데이터 확보**: 위 입력 조회 순서대로 진입가/손절가/목표가/청산가/최초 테제를 확보한다.
2. **정량 계산**: `tools/trading_rigor.py realized-pnl --entry <진입가> --stop <손절가> --target <목표가> --exit <청산가>`로 R-멀티플과 승패(win/loss/breakeven)를 계산한다.
3. **관점별 귀인 분석**: 최초 `/trade-team` 리포트를 찾을 수 있으면, `agents/trend-analyst.md` / `agents/macro-analyst.md` / `agents/risk-manager.md` / `agents/flow-analyst.md` 4개 관점 각각의 최초 판단(Bull/Bear/Neutral)이 결과적으로 맞았는지 한 줄씩 평가한다. 리포트를 찾을 수 없으면 이 표를 생략하고 "관점별 귀인 분석 생략 — 최초 리포트 없음"이라고 명시한다 (근거 없이 추정해서 채우지 않는다).
4. **교훈 추출**: 최소 1개 이상, 이번 결과에서 다음 유사 셋업에 적용할 구체적인 교훈을 서술한다. "다음엔 조심하자" 같은 추상적 문장 대신, 어떤 신호를 더 무겁게/가볍게 볼지처럼 행동 가능한 형태로 적는다.
5. **데이터 신뢰도**: 최초 `/trade-team` 리포트를 찾았으면 그 리포트의 "데이터 신뢰도" 집계 줄(`agents/README.md`의 표기 규칙)을 그대로 인용한다 — 이 스킬 자체는 새로 리서치하지 않으므로 새 등급을 매기지 않는다. 최초 리포트가 없으면 "데이터 신뢰도 인용 불가 — 최초 리포트 없음"이라고 명시한다.

## 출력 포맷

```
# /post-mortem 리포트 — <티커> (<기준일>, 청산일 <YYYY-MM-DD>)

## 실현 손익
| 방향 | 1R(진입~손절) | 계획 R | 실현 수익률 | 실현 R-멀티플 | 결과 |
|---|---|---|---|---|---|
| long/short | ... | X.XXR | ±X.XX% | ±X.XXR | win/loss/breakeven |

## 관점별 귀인 분석
| 관점 | 최초 판단 | 결과적으로 |
|---|---|---|
| 추세 | Bull/Bear/Neutral | 맞음/틀림/부분적으로 맞음 |
| 매크로 | ... | ... |
| 리스크 | ... | ... |
| 수급 | ... | ... |
(최초 리포트가 없으면: "관점별 귀인 분석 생략 — 최초 리포트 없음")

## 교훈
1. ...

## 데이터 신뢰도
🟢 N개 / 🟡 N개 / 🔴 N개 — 종합: 🟢/🟡/🔴 (최초 리포트에서 인용)
(최초 리포트가 없으면: "데이터 신뢰도 인용 불가 — 최초 리포트 없음")
```

## 리포트 저장

위 출력 포맷으로 작성한 리포트를 채팅 응답으로만 끝내지 않고, `reports/<날짜>-<티커>-post-mortem.md`에 파일로도 저장한다 (`reports/README.md` 규칙 — 실제 실행 결과는 이 폴더에 남긴다).

- 같은 티커를 다시 청산·재분석하는 경우는 드물지만, 같은 날 재실행하면 기존 파일을 덮어쓴다.
- 저장 후, 저장한 파일 경로를 사용자에게 알린다.
