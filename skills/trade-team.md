# /trade-team

## 목적

하나의 종목/자산에 대해 `agents/`에 정의된 4개 관점(추세·매크로·리스크·수급)을 **동시에 병렬 실행**시키고, 그 결과를 하나의 리포트로 종합한다. 4개 관점이 의도적으로 서로 다른 판단 기준을 쓰기 때문에, 의견이 갈리는 지점 자체가 정보다 — 절충하지 않는다.

## 입력

```
/trade-team <티커 또는 자산명>
```

## 실행 순서

### 1. 사전 점검

- 웹 검색 도구 사용 가능 여부를 먼저 확인한다. 사용 불가하면 **여기서 중단**하고 사용자에게 알린다 — 서브에이전트가 조용히 학습 지식만으로 답하는 것을 막기 위함이다.
- 대상의 "조사 가능성" 등급을 매긴다:
  - **A**: 공개 시장 데이터 충분 (상장 주식/ETF/주요 코인 등)
  - **B**: 부분적 (거래량·유동성 낮음, 데이터 일부 결측)
  - **C**: 정보 부족 (비상장, 신규 상장 직후 등) — 이 경우 각 에이전트 보고서에 데이터 한계를 명확히 요구

### 2. 팀 구성

- team-lead = 이 스킬을 호출한 메인 에이전트 자신
- 4개 작업으로 분해:
  1. 추세 분석 → `agents/trend-analyst.md`
  2. 매크로 분석 → `agents/macro-analyst.md`
  3. 리스크 분석 → `agents/risk-manager.md`
  4. 수급 분석 → `agents/flow-analyst.md`

### 3. 병렬 서브에이전트 호출

**같은 응답 안에서 4개의 서브에이전트 호출을 동시에** 낸다 (순차 호출 금지 — 순차로 하면 병렬의 의미가 없다).

- 각 호출의 프롬프트에는 다음을 모두 포함한다:
  - 대상 서브에이전트가 참고할 `agents/*.md` 파일 전체 내용
  - 분석 대상 티커/자산명과 오늘 날짜
  - 아래 "4. 서브에이전트 공통 규율"
  - "완료되면 team-lead에게 보고서를 보내라"는 지시

### 4. 서브에이전트 공통 규율 (모든 프롬프트에 필수 포함)

- 최신 데이터를 웹 검색으로 확인한다. 학습 지식만으로 최신 가격/실적/지표를 단정하지 않는다.
- 핵심 수치는 **2개 이상 독립 출처**로 교차검증한다. 출처 간 오차가 크면(기준: 1% 초과 또는 방향이 다른 경우) 그 사실을 보고서에 명시한다.
- 웹 검색이 막히거나 데이터가 없으면 "⚠️ 미확인"으로 명시한다. 없는 데이터를 있는 것처럼 서술하지 않는다.
- 출력은 해당 `agents/*.md`에 정의된 출력 포맷을 그대로 따른다.
- 계산이 필요한 값(수익률, 비율 등)은 암산하지 말고 `tools/`의 검증 스크립트가 준비되면 그것을 사용한다 (아직 없다면 계산 과정을 명시적으로 보여준다).

### 5. 종합 (team-lead)

4개 보고서가 모두 도착하면:

1. **4차원 점수표** 작성 — 각 에이전트의 점수(0~5)와 Bull/Bear/Neutral 태그를 한 표에 나란히 놓는다.
2. **한줄 결론** — 4개 관점을 절충한 문장이 아니라, 점수 분포 자체를 요약한다.
3. **의견 불일치 처리**:
   - 4개 태그가 대체로 일치 → 해당 방향으로 명확히 판정
   - 태그가 갈리거나 점수 분산이 크다 → **Gray Zone**으로 명시하고, 왜 갈리는지(어느 관점이 어느 관점과 충돌하는지) 설명한다. 억지로 하나의 결론으로 합치지 않는다.
4. **리스크 관리자의 실패 시나리오**는 항상 별도로 강조 노출한다 (다른 관점이 아무리 강세여도 생략하지 않음).
5. **3단계 대응 전략**: 공격적 / 온건적 / 보수적 진입 기준을 가격 구간과 함께 제시한다.

### 6. 출력 포맷

```
# /trade-team 리포트 — <티커> (<기준일>)

## 한줄 결론
<Gray Zone 여부 포함>

## 4차원 평가
| 관점 | 태그 | 점수 | 핵심 근거 |
|---|---|---|---|
| 추세 | Bull/Bear/Neutral | X/5 | ... |
| 매크로 | Bull/Bear/Neutral | X/5 | ... |
| 리스크 | Bull/Bear/Neutral | X/5 | ... |
| 수급 | Bull/Bear/Neutral | X/5 | ... |

## 의견 충돌 지점
- ...

## 리스크 관리자 — 실패 시나리오
1. ...

## 대응 전략
| 전략 | 권장사항 | 가격/조건 범위 |
|---|---|---|
| 공격적 | ... | ... |
| 온건적 | ... | ... |
| 보수적 | ... | ... |

🟢/🟡/🔴 <요약>
```

## 비용 관리

이 스킬은 4개 서브에이전트를 병렬로 띄우므로 토큰 비용이 크다. 저비용 스크리닝 스킬이 먼저 준비되면, 그걸로 후보를 거른 뒤에만 `/trade-team`을 실행하는 것을 권장한다 (`docs/architecture.md` 참고).
